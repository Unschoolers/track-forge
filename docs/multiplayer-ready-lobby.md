# Multiplayer ready lobby

Every new race, retry, changed circuit and Cup round is proposed by the host. The existing room stays connected. Track transfer validates the course before a guest enters the lobby; downloading the track is not consent. Each player chooses a car (duplicates allowed), sees the standard car specifications and explicitly readies up. Previous cars persist, consent resets per round. All players cancel their consent before changing a committed car; guests additionally wait for host acknowledgement. The host locks the lineup atomically when all current participants have accepted. The existing scene-ready handshake remains independent of consent.

Protocol v4: ready messages carry accepted and a monotonically increasing choice counter per round; host roster messages carry a revision. Older clients fail the existing version gate. Pose/progress packet formats do not change. Only the host proposes a course, owns roster membership and stages the lineup. Stale round/revision packets must not unlock or start a race.

Validation: multiplayer component/in-memory network tests, control decoder, application navigation, mobile UI and full CI. Real Android and Windows device pairing and multi-round readiness remain device QA requirements.

Lobby navigation: Close, Back and Escape use the same controller-owned leave confirmation for connected races, including rematches and Cup rounds. Stay (or dismiss the confirmation) retains the connection, selected car and consent; only explicit Leave disconnects. Hosting warns that leaving closes the room for everyone. An incoming race start or disconnect supersedes the confirmation rather than trapping the player in a stale dialog.

Presentation: single-player race setup and multiplayer lobby share `racePreparationLayout.ts`, the actual track flyover, car picker, performance meters, and responsive preparation styles. Portrait uses a single column; at 640 CSS pixels and wider the car picker and mode-specific panel sit side by side. Solo retains lighting, race mode, ghost availability, Options and Start; multiplayer retains the compact eight-player roster, confirmed readiness and Leave. Multiplayer previews the validated proposed track, not the current solo selection. Flyover playback is retained across lobby updates and renderer resources are cleaned up when leaving. The footer remains visible while the body scrolls. Ready is shown in green only after host confirmation, with explicit confirming/updating/choosing/loading states. The selected car remains highlighted while locked. Course metadata includes lighting, laps and Cup round. No new wire fields or physics changes.

Reliable lobby roster and track deliveries are isolated per recipient. Native rejection may precede disconnect notification: the host allows a bounded 500 ms reconciliation window, continues only when membership or round is obsolete, and reports genuine live-peer delivery failures instead of hiding them. Track transfer uses current membership for every chunk and must finish before the lineup is locked.

The host waits for every outstanding roster broadcast to settle before committing the lineup, including membership reconciliation after a rejected delivery. Choice send failures are scoped to the current round and revision: a superseded or host-acknowledged choice is recorded as obsolete, while a failed current, unacknowledged choice still reports an error. A valid committed lineup supersedes outstanding lobby choices.

Roster sends are serialized independently per peer: one in flight and at most one newest queued full snapshot. Superseded failures are diagnosed and repaired by the latest snapshot; failure of the latest live-peer delivery is still fatal. The final staging barrier waits until all current peer queues drain. This bounds reliable network work without delaying a fast peer behind a slow one.
